# WORKSPACE · 造物间

个人 AI 创作资料库，使用 HTML、CSS、JavaScript 和 Node.js 内置模块，无第三方运行依赖。

## 本机运行

需要 Node.js 22 或更新版本，以及随 Node.js 提供的 npm。在源码目录运行：

```sh
npm start
```

然后打开 [http://127.0.0.1:4173/](http://127.0.0.1:4173/)。无需先安装依赖；关闭运行服务的终端后，网站停止服务，已保存资料仍保留。首次使用是空库，可在网页中添加资料和图片。

首页显示 WORKSPACE，点击 EXPLORE 进入创作库。支持人物、提示词、素材、项目、作品、工作流、灵感和实验记录，以及搜索、收藏、关联资料、图片上传与原图下载。

## GitHub 与部署

此仓库保存源码，不包含个人资料、上传图片或开发截图。当前版本依赖 `server.mjs` 提供资料保存、图片上传和下载接口，**不能直接在 GitHub Pages 运行完整功能**；仅上传静态网页文件不会提供这些接口。

当前服务器只监听本机 `127.0.0.1`，检查本机 Host 与写入请求来源，尚未实现多用户登录。若要部署在线网站，需要支持 Node.js 和持久存储的服务，并按部署平台配置监听地址、域名访问规则及身份认证。仓库本身未配置自动部署。

## 数据与备份

- 资料：`data/library.json`。
- 上传图片：`data/uploads/`。
- 完整备份：先停止服务，再复制整个 `data/` 文件夹到自己的备份位置。
- 恢复：停止服务后，将备份的 `data/` 放回源码目录，再运行 `npm start`。

网页的 JSON 导出包含资料和图片路径，**不包含图片文件**。图片需要随 `data/uploads/` 一起备份，或使用网页中的“下载图片”。`.gitignore` 会排除个人数据、图片目录和本地配置，勿将备份加入源码仓库。

可通过 `PORT` 修改本机端口，通过 `LIBRARY_DATA_DIR` 指定独立资料目录；默认使用项目中的 `data/`。

## 检查

```sh
npm test
```

下载检查使用系统临时目录和随机本机端口，验证图片原始字节、中文文件名、响应头和普通图片展示，完成后清理测试进程与临时目录，不操作个人资料。

`scripts/verify-local.mjs` 另提供完整资料接口检查。手动使用前，应先启动专用测试服务，用 `LIBRARY_DATA_DIR` 指向空的临时目录，再将 `LIBRARY_TEST_URL` 指向该服务。该脚本会写入临时记录并清理；上传的测试图片路径会打印在结果中，供清理测试目录时核对。

## 文件

- `public/`：实际网页、交互、样式及网站图标。
- `server.mjs`：本机资料接口、上传下载与网页服务。
- `scripts/`：接口与下载验证脚本。
